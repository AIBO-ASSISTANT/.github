# Support

This project is currently maintained as an active engineering ecosystem, not a public production SaaS support desk.

## Where to Ask

| Need | Path |
| --- | --- |
| Bug report | Open a bug issue using [ISSUE_TEMPLATE/bug_report.yml](ISSUE_TEMPLATE/bug_report.yml). |
| Feature request | Open a feature request using [ISSUE_TEMPLATE/feature_request.yml](ISSUE_TEMPLATE/feature_request.yml). |
| Architecture question | Open an architecture proposal or discussion issue. |
| Security concern | Follow [SECURITY.md](SECURITY.md). Do not open a public vulnerability issue. |
| Local setup issue | Start with [onboarding/local-setup.md](onboarding/local-setup.md), then open a task or bug with environment details. |

## Maintenance Expectations

- Issues should include reproduction steps, expected behavior, actual behavior, and affected repository.
- Support requests without enough detail may be closed with a request for clarification.
- Maintainers prioritize security, data-loss risk, broken main branch, and blocked contributors before feature requests.

## Not Yet Supported

- Production uptime guarantees
- Hosted customer support
- SLA-backed incident response
- Managed deployment environments
- External integration support for unimplemented integrations
