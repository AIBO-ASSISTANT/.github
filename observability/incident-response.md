# Incident Handling

Incident process is planned. This document defines expected behavior once production or shared staging exists.

## Severity

| Severity | Meaning |
| --- | --- |
| SEV1 | Data loss, security incident, or total production outage. |
| SEV2 | Core workflow unavailable or severely degraded. |
| SEV3 | Partial degradation with workaround. |
| SEV4 | Minor issue or low-risk operational defect. |

## Incident Flow

1. Declare incident and owner.
2. Stabilize user impact.
3. Capture timeline.
4. Communicate status.
5. Mitigate or roll back.
6. Verify recovery.
7. Write follow-up with root cause and actions.

## Rule

Incident review is blameless but action-oriented. The output must be fixes, monitoring, documentation, or process changes.
